UX-OS / Research

Research

Interviews, surveys, usability tests, diary studies, card sorts, affinity diagrams, empathy maps, personas, journey maps, jobs to be done and research repositories.

Left alone, Claude will write you a persona from nothing. This set gives it a method for asking real people first.

What's missing: So far these have only run on made-up test data, and none has been compared with no skill at all.

How to run it

Install it once. You need Claude Code, and Node for the checking scripts.

/plugin marketplace add bbulman/ux-os
/plugin install ux-os@ux-os

Everything here is typed by name, and every name starts with /ux-os:. Not sure where to start? /ux-os:research-next says where an idea stands and the one thing to do now.

Personas, journeys, jobs and empathy maps each take a switch. proto builds from what you believe and labels it an assumption. real builds from your files, and every line links to the exact passage it came from. Real needs at least 5 people from different organisations, and stops if you don't have them.

Run /ux-os:init once per project and deliverables take your design system's fonts and colours. Design proposals then name a real component, or say none fits.

Example prompts

Swap volunteer-rota for your own idea, in two to four words.

  • I have an idea and no data yet.

    /ux-os:research-discover volunteer-rota

  • I want a quick persona from what I already believe.

    /ux-os:create-personas volunteer-rota proto

  • I've finished my interviews and want real personas.

    /ux-os:create-personas volunteer-rota real --evidence ~/interviews/

  • New notes have come in.

    /ux-os:research-debrief volunteer-rota --evidence ~/interviews/week-2/

  • I've talked to five organisations and want to stop guessing.

    /ux-os:research-synthesize volunteer-rota

  • I don't know what to do next.

    /ux-os:research-next volunteer-rota

  • I want deliverables to look like our design system.

    /ux-os:init

Commands: run a whole stage, or set up a project

research-next

Says where a research idea stands and the one thing to run next. It reads the folder and changes nothing.

Testing: Typed as a real command on a made-up idea, and it named the right next step. The routing has its own self-test.

The one-command-now shape comes from MC Dean's start-here command in the Designer Skills Pack.

Example prompts

/ux-os:research-next volunteer-rota
Run by name

research-discover

Asks what you believe about a new idea, once, then builds your first jobs, personas and journey from it and names the one belief to test first.

Testing: Run by an agent following the files, on made-up test data only.

Chaining models into one command comes from MC Dean's discover command in the Designer Skills Pack.

Example prompts

/ux-os:research-discover volunteer-rota
Run by name

research-debrief

Takes in a new interview or study, removes the names, and shows which beliefs it bears on, without rewriting anything you built.

Testing: Run by an agent following the files, on made-up test data only.

Example prompts

/ux-os:research-debrief volunteer-rota --evidence ~/interviews/week-2/
Run by name

research-synthesize

Once enough evidence is in, sorts it, summarises it, settles each belief and rebuilds your proto models on what people did.

Testing: Run by an agent following the files, on made-up test data only.

Chaining synthesis into one command comes from MC Dean's synthesize command in the Designer Skills Pack.

Example prompts

/ux-os:research-synthesize volunteer-rota
Run by name

record-decision

Records what you decided because of the research, what the decision rests on and what would reverse it. A decision made on a belief stays in pencil.

Testing: The rules its file is checked against have their own self-test and one independent review. The typed command has not been run yet.

Example prompts

/ux-os:record-decision volunteer-rota
Run by name

init

Connects a project's design system once. Deliverables take its fonts and colours, and each design proposal names a real component or says none fits. It shows you everything before saving.

Testing: Connected to one real design system with 133 components. The step that saves it has its own self-test, and running it twice changes nothing.

Example prompts

/ux-os:init
Run by name

Skills: each makes one deliverable

affinity-diagram

Sorts real research notes into themes from the bottom up, counts people rather than notes, and has a second agent re-sort them blind. Needs data to work from.

Testing: Test run: 4 of 26 notes landed differently in the blind re-sort. Run on made-up test data only.

Example prompts

/ux-os:affinity-diagram volunteer-rota --evidence ~/interviews/
Run by name

analyze-card-sort

Works out how people grouped your cards: how often pairs stayed together, the groups that form, and the cards with no clear home. Needs real results.

Testing: Analysis script with its own self-test. Run on made-up test data only.

Example prompts

/ux-os:analyze-card-sort volunteer-rota --evidence ~/exports/card-sort.csv
Run by name

create-empathy-map

Maps what one person says, does, thinks and feels in one moment, and where saying and doing come apart. Works from your beliefs or from real research.

Testing: Checking script with its own self-test. Run on made-up test data only.

Example prompts

/ux-os:create-empathy-map volunteer-rota real --evidence ~/interviews/
Run by name
