Build one by interview

One command interviews you and writes JOURNEYS.md. The interview works the way /grill-me does: it settles every decision the file rests on, one round of questions at a time, until nothing is left assumed. Run it after PERSONAS.md, whose personas it maps.

/ux-os:create-journeys-file

It reads first

PERSONAS.md, PRODUCT.md, the research folder and any journeys a research run wrote.

Then it asks about

  1. Which journeys: one per primary persona
  2. For each: the scenario, where it starts and ends, five to seven stages, and how each stage feels
  3. Two or three moments that matter
  4. Whether to add a future journey

How it runs

  1. It looks up every fact it can before asking anything, and in a file that already exists it tests each claim against the code.
  2. It asks in rounds, and each question comes open: it offers its own draft only after you answer or say you have no view, because this file has to hold what you believe, not what it guessed.
  3. It shows a summary of the new file, section by section, and writes nothing until you say yes.
  4. A missing file, or one still the unfilled template, is written at the project root. A file that already exists is never changed: the new copy goes to .scratch/project-files/JOURNEYS.md, with the facts it corrected and any citations into the old file that would break, for you to compare.

JOURNEYS.md (Workshopr example)

An excerpt from Workshopr's own JOURNEYS.md, trimmed to show the shape. Sections left out are marked.

Four persona-specific, current-state journey maps for workshopr.io, one per persona in PERSONAS.md (Maya, Devin, Priya, Marcus). Method: Kalbach-style experience mapping. Each map covers six stages with goals, actions, touchpoints, thinking, an emotion score from -2 to +2, pain points, and opportunities.

⚠️ Research note: Like the personas, these maps are provisional (reasoned, not yet validated by primary research). No interview transcripts or survey analysis behind them are on file. Emotion scores are interpretive rather than measured.

Reading the maps: stages run left to right; ★ marks a moment of truth, the point where the experience is won or lost. Feeling is scored -2 (worst) to +2 (best).

Maya Okonkwo: one client engagement, end to end

Scenario: a paid half-day strategy workshop for a repeat-curious client. Boundaries: from the discovery call to the moment the next engagement is (or isn't) won.

Emotional curve: +1, +2, +1, +2, +1, -1. High through craft and delivery, then drops exactly where the product ends today: after send.

Moments of truth:

  • ★ The same-evening recap. If it lands while the energy is warm, she looks exceptional; the whole product pays off here.
  • ★ "Where did this theme come from?" Provenance answers the client challenge in seconds; without it, trust in the recap (and in her) wobbles.

Top opportunities: 1) Impact report and commitment tracking to close stage 6 (impact High, feasibility Mid). 2) Branded exports so stage 5 ends inside the product (High, High). 3) Client-facing agenda share for prep (Mid, High).

Validation note

Emotion scores, the two-minute ceiling, the minute-12 freeze, and the seat-purchase dead end are all hypotheses. The research plan in PERSONAS.md (time-and-pain interviews, retro diary study, first-workshop interviews, buyer interviews, funnel data) doubles as the validation plan for these maps; run it before re-sequencing the roadmap on their basis.
