Install once · then each project

Get started

Install UX-OS once in Claude Code, then set up each project so every skill starts from the same facts. You need Claude Code, and Node for the checking scripts.

Install

Two ways, pick one

  • Just UX-OS

    The ux-os plugin: my research commands and the commands that set up a project. Enough for everything below.

    Once, in Claude Code

    /plugin marketplace add bbulman/ux-os
/plugin install ux-os@ux-os

  • Everything I run

    My whole loadout: the 17 plugins I keep on, ux-os among them, from three marketplaces, and the settings that keep the rest to run by name.

    Once, from the Loadout page

    Copy my loadout

Start a new project

Four steps, in order

  1. 1. Write the project files

    Sets up a project's nine UX-OS files (PRODUCT, DESIGN, AGENTS, PERSONAS, JOURNEYS, JTBD, taste, motion and VOICE) from annotated templates, writing only the ones that are missing.

    What each file is for, and which skills read it

    In the project

    /ux-os:create-project-files

  2. 2. Fill each one by interview

    Each file has its own command. It reads the code and the other files first, asks in rounds with a recommended answer to each question, and writes nothing until you agree a summary. A file that already exists is never changed: the new copy goes to .scratch/project-files/ for you to compare.

    Start with PRODUCT.md: every other file defers to it.

    In this order

    1. PRODUCT.md /ux-os:create-product-file
    2. DESIGN.md /ux-os:create-design-file
    3. taste.md /ux-os:create-taste-file
    4. VOICE.md /ux-os:create-voice-file
    5. motion.md /ux-os:create-motion-file
    6. PERSONAS.md /ux-os:create-personas-file
    7. JOURNEYS.md /ux-os:create-journeys-file
    8. JTBD.md /ux-os:create-jtbd-file
    9. AGENTS.md /ux-os:create-agents-file

  3. 3. Connect your design system

    Connects a project's design system once. Deliverables take its fonts and colours, and each design proposal names a real component or says none fits. It shows you everything before saving.

    Once per project

    /ux-os:init

  4. 4. Start on an idea

    Says where a research idea stands and the one thing to run next. It reads the folder and changes nothing. Give the idea a short name, and its work collects in ux-os/<idea>/.

    Or find the skill for a job

    Whenever you are not sure what to do next

    /ux-os:research-next <idea>
