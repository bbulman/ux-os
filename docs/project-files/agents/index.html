Build one by interview

One command interviews you and writes AGENTS.md. The interview works the way /grill-me does: it settles every decision the file rests on, one round of questions at a time, until nothing is left assumed. Run it last: it points at all the others.

/ux-os:create-agents-file

It reads first

The agent guide (CLAUDE.md or its equivalent), any other agent instruction files, the CI configuration, the deploy scripts, the environment example, any agent hooks and the test commands.

Then it asks about

  1. Which file is the guide
  2. Which other files an agent must read, and when
  3. The guardrails, where a mistake is expensive or hard to undo
  4. What finished means here

How it runs

  1. It looks up every fact it can before asking anything, and in a file that already exists it tests each claim against the code.
  2. It asks in rounds: every question it can ask yet, numbered, each with its recommended answer and the reason, worded so that "yes" accepts it.
  3. It shows a summary of the new file, section by section, and writes nothing until you say yes.
  4. A missing file, or one still the unfilled template, is written at the project root. A file that already exists is never changed: the new copy goes to .scratch/project-files/AGENTS.md, with the facts it corrected and any citations into the old file that would break, for you to compare.

The guardrails

[Section left out: operational guardrails specific to the codebase.]

Never introduce a frontend framework. Vanilla JS and CSS only, no React, no Vue, no bundler, unless a human explicitly asks.

Every UI change uses the design system. Reach for an existing component before writing HTML. Colours, spacing, type, radii and shadows come from the tokens, never a hex or pixel value where a token exists, and the fonts are Fraunces for headlines and Inter for body. Before calling UI work done, run the design-system check and load the page.

Definition of done

Exercise the change; do not just make it compile. Load the affected page or hit the endpoint, run the relevant test, and for a bug fix add or update one. For any UI change the design-system check must pass and the page must render correctly.
