Method

How a skill gets built

This is the method so far. It comes from building the information-architecture skill, the first one to go through full testing. Steps 1 to 5 are what I did on that skill. Steps 6 to 8 are what it showed I should add.

  1. Check what already exists

    Search the registry and the installed skills first. The information-architecture skill started because two public skills with the same name could not be installed together.

  2. Decide how to get it

    Adopt a good skill as it is, combine several when each covers part of the job, or write one when nothing fits.

  3. Check the licence

    Without an open licence I rewrite and never copy.

  4. Write the skill and its tests together

    SKILL.md holds the method, references/ holds long material such as methodology, templates and a rubric, and evals/ holds realistic test cases.

  5. Test it against no skill at all

    Run each case with and without the skill using skill-creator, grade both, fix what failed and run it again. Record the score and the cost.

  6. Test the real name

    Ask a fresh session to quote the skill's entry in its list. With this many skills installed, most appear by name only, so the name has to say what the skill is for and rewriting the description changes nothing. Test with the real name, because the tuning tool in skill-creator uses a copy with a temporary name, which can lose to a competing skill for that reason alone.

  7. Check Claude can reach it

    Confirm no skillOverrides entry hides it and no installed skill with the same name competes with it.

  8. Register it

    Add a row to the registry and write down how it was built.

What testing showed on the first skill

The first round scored 24 of 25 with the skill and 23 of 25 without, which is almost no benefit. After fixes and sharper checks, the second round scored 29 of 29 with the skill and 22 of 29 without. The third round, on the published version, scored 28 of 29 against 19 of 29. In those last two rounds the skill made runs 49% to 73% longer and used 19% to 26% more tokens, so the cost belongs in the record beside the score.

The skill, its test cases and every grade are on GitHub.

Trigger testing then showed how much the name matters. The tuning tool in skill-creator scored 0 of 10, with a rival skill winning 9, but its test copy carries a temporary name. With the real name, Claude chose the skill on 9 of 10 requests and on none of 10 near-misses.

When a skill changes

Rerun its evals after any edit instead of changing it ad hoc.

A pile of skills is not a system

On 24 October I built an information-architecture skill, because two public ones shared a name and couldn't be installed together. Then I tested it against no skill at all. With the skill: 24 out of 25. Without it: 23.

One point. Installing a skill told me nothing about whether it helped, or whether Claude would ever open it. An operating system answers those questions for programs: what's loaded, who gets priority, what each one costs. UX-OS answers them for skills. It's four jobs you do on whatever you've got, and the record of how they came out.

  1. 36 of 505

    Roughly, in one project of mine: skills that get a description in Claude's list

    Decide what loads.

    With that many installed, the rest show up as a bare name, so a better description changes nothing. So each entry gets a decision, made in Claude Code's own settings: load it, keep it for when I call it by name, or switch it off. ON, BY NAME and OFF in the registry are those decisions. To see yours, ask a fresh session to quote its skill list.

  2. 9 of 10

    requests chosen under its real name. Under a temporary test name: 0 of 10

    Settle who wins.

    Two skills can claim the same job. With a temporary test name, mine won none of ten requests and a rival took nine. Under its real name, Claude chose it nine times out of ten, and on none of ten near-misses. The name is the interface.

  3. 28 vs 19

    of 29 checks in the latest round, with the skill and without

    Make each skill earn its place.

    After that first round I fixed what failed and sharpened the checks. The gap has held for two rounds since, and every grade is public.

  4. +49%

    longer runs in the latest round, and about 19% more tokens

    Put the cost beside the score.

    Better answers aren't free. When the number's written down, you get to decide when it's worth paying.

One skill, three test cases, and I wrote both the skill and the checks. That's a field note, not a study.

The case against all this: skills are cheap, so install everything and let Claude sort it out. Fair. That's how I got to 505. Then I asked Claude to show me what it could actually see.

How this registry stays true

One registry file holds every entry. The counts the site prints around it, on every page, are worked out from the data each time the site is built.

Whether it loads

ON, BY NAME and OFF come from scripts/scan.mjs. It reads what is installed on this machine and whether Claude can load it, then checks the registry against that. Run with --write, it sets each entry's status to what the machine says. What it reads stays on the machine.

How often I use it

Usage comes from scripts/usage.mjs. It counts three things in Claude Code transcripts: skills Claude started itself, commands typed by name, and agents handed work. An MCP server counts its tool calls. Only registry ids and numbers are written down: no paths, prompts or project names. The current count starts on 22 July 2026 and covers one machine.

What the build refuses

build/load.mjs stops the build on an unknown set, type, origin, status, scope or stage, on a job or workflow step that names something not in the registry, on a story or template file that does not exist, and on any published string that holds a local path or an email address. It reports every problem in one run, then refuses to write a page.

After the build, scripts/check-links.mjs follows every link between pages and fails if one is broken or an entry page is missing from the registry.

As of 14 November 2026: 135 entries, 67 ON, 59 BY NAME and 9 OFF. 44 have been used since 22 July 2026, and 77 have a test result written down. What changed, and when.
