One command interviews you and writes motion.md. The interview works the way /grill-me does: it settles every decision the file rests on, one round of questions at a time, until nothing is left assumed. Run it after DESIGN.md.

/ux-os:create-motion-file

It reads first

The motion tokens, the animation code, any motion docs in the design system, and every place the code handles reduced motion.

Then it asks about

  1. Three words for how motion should feel, each with what it rules out
  2. The standard values, only where the code and the file disagree
  3. Five patterns or fewer, each with its values
  4. What motion must never do
  5. What changes when someone asks for less motion
  6. The stack, and what is ruled out

How it runs

  1. It looks up every fact it can before asking anything, and in a file that already exists it tests each claim against the code.
  2. It asks in rounds: every question it can ask yet, numbered, each with its recommended answer and the reason, worded so that "yes" accepts it.
  3. It shows a summary of the new file, section by section, and writes nothing until you say yes.
  4. A missing file, or one still the unfilled template, is written at the project root. A file that already exists is never changed: the new copy goes to .scratch/project-files/motion.md, with the facts it corrected and any citations into the old file that would break, for you to compare.

How to Use This

This isn't a reference doc for you to memorize. It's context for Claude. When this file is loaded, Claude will:

  • Reach for the right vanilla technique for each animation type (CSS transitions, @keyframes, or IntersectionObserver)
  • Use your project's exact easing, timing, and motion values
  • Avoid common pitfalls (layout shift, re-triggering, jarring motion)
  • Keep motion subtle and premium: never theme-park

Just describe the feeling you want. Claude handles the implementation.

Motion Language

The project has a specific motion personality. All animations should feel:

  • Unhurried: nothing snaps or pops. Things drift into place.
  • Confident: elements don't bounce or overshoot. They arrive and stay.
  • Quiet: motion supports content, never competes with it.

Think: a page that breathes rather than performs.

The Standard Values

These are the page-reveal regime values. Claude must use them by default for marketing/landing reveals and hero sequences. (In-app UI micro-motion, meaning hovers, modals and toggles, uses shorter 150–300ms durations.)

Ease:         cubic-bezier(0.22, 1, 0.36, 1)   (soft deceleration, things slow into rest)
Duration:     0.8s – 1.2s            (scroll reveals)
              1.2s – 1.4s            (large elements, hero sequences)
              0.8s – 0.9s            (labels and metadata fading in within a reveal sequence)
Max Y offset: 16–32px                (never more: subtle, not theatrical)
Max X offset: 0px                    (things move vertically, not sideways)
Stagger gap:  0.12s per item         (UI micro-motion staggers 30–50ms)
Viewport trigger: rootMargin "-15%" to "-20%"  (trigger before element fully enters view)

Express these as CSS custom properties so every component pulls from the same values instead of hardcoding numbers.

Anti-Patterns (What Claude Must Avoid)

Don'tWhyDo Instead
Animate elements more than onceFeels restless, breaks premium feelunobserve() after first trigger, always
Move things sideways on scrollFeels gimmicky, breaks vertical rhythmVertical movement only
Use overshoot/bounce easing (curves that go past 1)Too playful for this brandUse cubic-bezier(0.22, 1, 0.36, 1). The spring-named easing in the system is pure deceleration and does NOT overshoot despite its name, so it is allowed
Translate more than 32pxDraws too much attention to the motion itselfKeep it 16–24px
Animate to full opacity for labelsSupporting text should stay subduedTarget 0.4–0.7 for metadata
Animate layout properties (top, left, width, height, margin)Triggers layout/paint, causes jankAnimate transform and opacity only
Add scroll-jacking or position-lockingFrustrates users, fights native scrollLet the page scroll naturally
Re-trigger reveals on every scroll passRe-triggering looks broken and restlessAlways unobserve after the first intersection
Install animation libraries (Framer Motion, GSAP, Lenis, etc.)Fragments the stack, pulls in a framework this project doesn't useCSS transitions/@keyframes + IntersectionObserver
Ignore prefers-reduced-motionAccessibility requirement, not optionalAlways gate non-essential motion behind the media query
