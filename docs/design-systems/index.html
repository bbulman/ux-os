Design systems

Tokens, components, naming, governance and documentation.

Claude reaches for whatever value looks right. These hold it to the tokens and components you already chose.

What's missing: ds-kit builds and changes a system now, from foundations to release, but it has never run on a real public website.

Jobs

What I hand to which skill in design systems. All the jobs

  1. Check UI against the design system while building

    Pick Design System Enforcer MCP: design-system-enforcer ONLoads on its own

    My most used tool by far. Names the component to use and flags hardcoded values.

  2. Start a design system from a live website

    Pick create-design-system /ds-kit:create-design-system ONLoads on its own

    Measures the site's real styles across pages and records where every value came from.

  3. Choose a visual direction before tokens exist

    Pick create-moodboard /ds-kit:create-moodboard ONLoads on its own

    Two or three directions to pick between, written down so the next stage can build from the pick.

  4. Change a token's value

    Pick update-ds-tokens /ds-kit:update-ds-tokens ONLoads on its own

    Even the one-line changes, so nothing downstream breaks quietly.

  5. Rename or remove a token or component

    Pick migrate-ds /ds-kit:migrate-ds ONLoads on its own

    Ships a codemod, not a find and replace.

  6. Audit an existing design system

    Pick audit-system /design-systems:audit-system ONLoads on its own

    Consistency, completeness and accessibility in one pass.
