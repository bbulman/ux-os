Prototyping

Wireframes, user flows, concept selection, prototype strategy, test plans and heuristic evaluation.

A prototype exists to kill an idea cheaply. This set decides what to build, how rough it can be and what counts as a pass.

What's missing: Design OS links the object map, sitemap, flows, screens, wireframes and a lo-fi prototype into checked files. It has passed on one worked example, not on a real project.

Jobs

What I hand to which skill in prototyping. All the jobs

  1. Draw a flow before any screens exist

    Pick create-interaction-flows /design-os:create-interaction-flows ONLoads on its own

    Includes what happens when the task goes wrong, and a script fails if a later stage drops a step.

    Rival user-flow-diagram draws a standalone diagram; the Design OS flow is a file the screen inventory and wireframes must agree with.

  2. List every screen a feature needs

    Pick create-screen-inventory /design-os:create-screen-inventory ONLoads on its own

    Each screen with its loading, empty, error and permission states, checked against the flow.

  3. Wireframe a feature

    Pick create-wireframes /design-os:create-wireframes ONLoads on its own

    Greyscale screens as files the next stages read. Plain Claude draws well already; the value is that the chain is checked.

  4. A clickable prototype to test a flow

    Pick create-lofi-prototype /design-os:create-lofi-prototype ONLoads on its own

    Built from the wireframes, so every arrow in the flow is clickable or the check fails.

  5. A quick throwaway build to feel something out

    Pick prototype /mattpocock-skills:prototype ONLoads on its own

    Built to be thrown away, which keeps it fast.
