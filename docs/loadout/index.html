3. Merge the settings

false keeps a plugin installed but never loaded. user-invocable-only keeps a skill out of Claude's list until you type its name: those 35 are my own skills, and the setting only matters if you have them installed.

What it can't control

Synced copies: a plugin added through claude.ai loads from a synced copy whenever claude.ai says it should, even when these settings say false. Switch those off in claude.ai itself. design only ever arrives that way.

Private: design-os, ds-kit, design-agent, feature-plan, feature-build and landing-page-design load from folders on my machine and aren't published, so they're left out.

Unnamed: lenny-skills research set, Emil Kowalski motion skills and Taste skills are kept by skill name in my own settings, and the registry doesn't list each skill, so they're left out too.

Projects: a project's own .claude/settings.json and settings.local.json can override all of this for that project.

Plugin skills: skillOverrides doesn't reach a plugin's skills. A plugin skill that runs only by name says so in its own file, which is why none appear in the block.
